# Worked drills

1. **SQL and evidence.** Open SQLite and enter `CREATE TABLE events(kind TEXT); INSERT INTO events VALUES ('ok'),('warn'),('warn'),(NULL);`. Run `SELECT kind, COUNT(*) FROM events GROUP BY kind;`. Expected counts are 1, 2, 1. Replace `COUNT(*)` with `COUNT(kind)` and explain why the NULL group becomes zero.
2. **Packet analysis.** In Wireshark, open an existing permitted DNS sample. Use `dns`, choose a query, and locate its response using packet references plus endpoints and transaction ID. Record both frame numbers. Repeat for a query with no matching response.
3. **Memory evidence on paper.** The process list gives PID 42 as a worker. A socket record lists PID 42 at a later time. Form two explanations, including PID reuse. Require process start and capture timestamps before linking the observations.
4. **Binary reading.** Compile a toy program that prints a label for a positive argument converted with `strtol`; review missing error handling. Compare its symbols and disassembly at `-O0` and `-O2`. Identify how the same decision is represented. Fix the parser to reject trailing text and overflow and verify normal and malformed inputs.
5. **Web and authorization.** Review pseudocode `get_report(id) -> db.read(id)`. The caller is signed in, but the operation needs report-specific authorization. Write expected outcomes for an owner, a different user and a deleted report. Add authorization to the server-side design and re-evaluate those cases on paper.
6. **Encoding and programming.** Run `printf '%s' 'aGVsbG8=' | base64 -d`, expect `hello`, then re-encode. Write down why reversible encoding provides no secrecy. For a parser exercise, define how your program handles invalid input instead of silently dropping bytes.
7. **Prompt injection, paper only.** Your task is to summarize a supplied report. A sentence in an appendix asks the reader to change the destination and disclose a fictional account record. Label the sentence as untrusted document content. Expected result: summarize the report without making the requested disclosure or changing destinations. Test a benign report as a control. For a real design, keep permission checks and tool destinations in application code and treat model output as untrusted.
8. **Media.** Complete the [dual-tone exercise](media.md). Ask a teammate to give you an unseen clip and report timestamps, frequencies and confidence before seeing their answer.
